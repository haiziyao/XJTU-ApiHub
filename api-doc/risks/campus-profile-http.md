# 校方学籍接口的明文 HTTP 链路

2026-11-23，项目决定将此项列为已知风险，继续讨论社区登录功能。涉及的社区接口为 [登录接口中的 `POST /api/auth/login`](../openapi/auth.json)。

Launcher 通过 HTTPS 发起学籍 OAuth 授权，授权请求指定的回调地址使用 HTTP。查询资料时，Launcher 优先通过 HTTP 请求校方的 `hello.xjtu.edu.cn/yingxin/user/afterLogin`，在请求头中携带学籍 token，并从响应读取学号、姓名和行政班级。

| 从 Launcher 部署服务器实测 | 2026-11-23 的结果 |
|---|---|
| HTTPS 学籍查询 | 首次请求 7 秒超时。复测时 TCP 443 连接在 15 秒后超时。 |
| HTTP 学籍查询，无凭证 | 约 0.06 秒收到 HTTP 200，业务状态为 `2000`，响应中没有学生资料。 |
| HTTP 学籍查询，有效 token | 通过官网 HTTPS 临时接口触发服务器请求，校方返回业务状态 `200`。学号与本机当前账号一致，姓名和行政班级均有值。见 [接口清单](../../api.md)。 |

客户端到 ApiHub 使用 HTTPS。若 ApiHub 通过公网 HTTP 向校方核验，能观察该段流量的一方可能读取学籍 token 和返回的个人资料；能修改流量的一方可能替换返回的学号，使 ApiHub 向错误身份签发社区登录凭证。校方接口支持 HTTP 是已观察到的兼容性事实，风险等级属于项目自身的判断。
